# unique_ptr 核心实现（移动语义版）

独占所有权智能指针 —— 从 AutoPtr 的坑到 UniquePtr 的优雅

---

## 📌 重点掌握

- 理解 `unique_ptr` 为何**删除拷贝**、只支持**移动**（独占所有权）。
- 能手写移动构造、移动赋值，实现所有权的**显式安全转移**。
- 重载 `operator*` 和 `operator->`，像原生指针一样使用。
- 明确 `auto_ptr` 被废弃的根本原因（破坏性拷贝）。

---

## 🔑 核心知识点（面试高频）

### 1. 左值 vs 右值（移动语义基础）

| 类型 | 定义 | 示例 | 能否取地址 |
|------|------|------|-----------|
| **左值 (lvalue)** | 有持久地址的对象 | 变量名 `int a = 10;`、`*p`、`arr[0]` | ✅ 能 |
| **右值 (rvalue)** | 临时对象，即将销毁 | 字面量 `42`、临时对象 `String("abc")`、`std::move(x)` | ❌ 不能 |

### 2. 为什么 `unique_ptr` 不能拷贝，只能移动？

| 操作 | 如果允许拷贝（错误） | 正确做法（移动） |
|------|---------------------|------------------|
| **拷贝构造** | 两个 `unique_ptr` 指向同一块堆内存 → 析构时 **double free**（崩溃） | 删除拷贝构造（`= delete`），编译期禁止 |
| **拷贝赋值** | 同样导致 double free 或内存泄漏 | 删除拷贝赋值（`= delete`） |
| **移动构造** | — | 转移指针，源置空，安全高效 O(1) |
| **移动赋值** | — | 释放自身旧资源，接管对方，源置空 |

### 3. 移动构造/移动赋值的实现要点（与 `String` 类一致）

| 要点 | 说明 |
|------|------|
| **参数必须是右值引用** | `MyUniquePtr(MyUniquePtr&& other) noexcept` |
| **标记 `noexcept`** | 保证容器（如 `vector`）扩容时可安全移动，否则退化为拷贝 |
| **窃取资源后置空源对象** | `other.ptr_ = nullptr;` 防止析构时 double free |
| **自赋值检测** | 移动赋值中检测 `if (this != &other)` 虽不必须（因为源是右值，通常不会自赋值），但更安全 |

### 4. `std::move` 的本质

> `std::move` 不移动任何东西，只是一个 **类型转换**：把左值强制转成右值引用，让编译器优先匹配移动版本。

```cpp
// 伪代码实现
template<typename T>
std::remove_reference_t<T>&& move(T&& t) {
    return static_cast<std::remove_reference_t<T>&&>(t);
}
