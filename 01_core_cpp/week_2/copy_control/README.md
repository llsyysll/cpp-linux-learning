# 拷贝控制

## 浅拷贝（Shallow Copy）

**定义**：只复制指针值（地址），不复制指针指向的内容。

**问题**：
1. 两个对象指向同一块内存 → 修改一个影响另一个
2. 析构时 double free → 程序崩溃
3. 悬空指针（一方释放后，另一方仍持有地址）

**什么时候发生**：
- 编译器自动生成的默认拷贝构造函数
- 编译器自动生成的默认拷贝赋值运算符

## 深拷贝（Deep Copy）

**定义**：复制指针指向的实际数据，分配新的内存。

**实现**：
- 在拷贝构造函数中分配新内存，复制数据
- 在拷贝赋值运算符中同样处理

## 何时需要自定义拷贝控制

**三/五法则（Rule of Three/Five）**：
> 如果类需要自定义析构函数，则一定需要自定义拷贝构造函数和拷贝赋值运算符。

| 成员函数 | 何时需要自定义 |
|---------|---------------|
| 析构函数 | 管理资源（堆内存/文件/锁） |
| 拷贝构造函数 | 管理资源时（深拷贝） |
| 拷贝赋值运算符 | 管理资源时（深拷贝） |
| 移动构造函数 | 需要移动语义优化 |
| 移动赋值运算符 | 需要移动语义优化 |

## 口诀

> **有析构，必有拷贝构造和拷贝赋值**
> **有拷贝构造，必有拷贝赋值（反之亦然）**

## 核心对比

| 特性 | 浅拷贝 | 深拷贝 |
|------|--------|--------|
| 复制内容 | 指针值（地址） | 指针指向的数据 |
| 内存 | 共享同一块内存 | 各自独立内存 |
| double free | ❌ 会 | ✅ 不会 |
| 修改影响 | 互相影响 | 互不影响 |
| 性能 | 快 | 慢（需要分配内存） |
| 安全性 | 低 | 高 |
